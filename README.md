# LanChat 1.7.1

پیام‌رسان مستقیم و مستقل برای شبکه محلی (LAN) ویندوز؛ بدون نقش مدیر، بدون سرور مرکزی و بدون حساب کاربری مرکزی.

## قابلیت‌ها
- هر رایانه یک همتای مستقل است؛ هیچ رایانه‌ای نقش مدیر یا سرور مرکزی ندارد.
- کشف خودکار همتاها از طریق UDP broadcast روی شبکه IPv4 و نمایش فهرست آنلاین.
- ارسال مستقیم پیام از یک رایانه به رایانه دیگر روی TCP.
- ذخیره محلی پیام‌های ارسال‌شده و دریافت‌شده در `%APPDATA%\LanChat\messages.txt`، در صورت فعال بودن گزینه ذخیره پیام.
- تنظیم نام نمایشی، پوسته روشن/تیره، نوع و اندازه فونت، اعلان پیام و پنجره روی همه برنامه‌ها.
- با زدن × پنجره مخفی می‌شود و برنامه کنار ساعت ویندوز در System Tray فعال می‌ماند؛ برای خروج کامل از منوی آیکون سینی، «خروج کامل» را انتخاب کنید.
- اعلان شامل پیام بالای پنجره‌ها نمایش داده می‌شود و در صورت فعال بودن اعلان، اعلان سینی ویندوز و صدای پیام نیز تلاش می‌شود.
- ایمیل تماس: `hamedmohammadinikche@gmail.com`

## نکات مهم شبکه
- برنامه باید روی هر دو رایانه اجرا باشد تا پیام مستقیم دریافت شود. **هیچ سرور یا رایانه‌ای برای رله پیام‌ها وجود ندارد**؛ اگر رایانه گیرنده خاموش باشد یا LanChat بسته باشد، پیام تحویل نمی‌شود و در صف ابری ذخیره نمی‌شود.
- رایانه‌ها باید در یک شبکه محلی قابل‌دسترسی باشند. شبکه‌های مهمان، جداسازی کلاینت در مودم، VPNها و بعضی شبکه‌های شرکتی ممکن است Broadcast یا ارتباط مستقیم را مسدود کنند.
- در فایروال ویندوز برای LanChat یا Python اجازه ارتباط در شبکه Private بدهید. پورت TCP `39872` و UDP `39873` استفاده می‌شوند.
- شناسه ثابت هر نصب در `%APPDATA%\LanChat\profile.json` ذخیره می‌شود. حذف این فایل شناسه جدیدی ایجاد می‌کند.
- پیام‌ها رمزنگاری سرتاسری نشده‌اند؛ برای شبکه‌های حساس استفاده نکنید.
- فهرست آنلاین بر اساس پیام‌های کشف دوره‌ای است و ممکن است چند ثانیه برای به‌روزرسانی زمان ببرد.

## ساخت EXE مستقل در GitHub
1. فایل‌های این پوشه را در مخزن GitHub قرار دهید.
2. در Actions گردش‌کار `Build LanChat for Windows` را اجرا کنید.
3. Artifact با نام `LanChat-Windows-1.7.1` را دریافت کنید؛ فایل داخل آن `LanChat.exe` است.

این نسخه در محیط توسعه از نظر نحوی بررسی می‌شود. برای اطمینان از کشف خودکار باید آن را روی دو رایانه واقعی در شبکه موردنظر آزمایش کنید.

# راهنمای توسعه‌دهندگان (فارسی)

این بخش برای کسی نوشته شده که می‌خواهد کد را مطالعه، اشکال‌زدایی یا توسعه دهد. فایل اصلی برنامه `main.py` است و بیشتر منطق در همان فایل قرار دارد.

## نقشهٔ فایل‌ها

- `main.py` — کد رابط کاربری، شبکه، ذخیره‌سازی، اعلان‌ها، تنظیمات و نقطهٔ شروع برنامه.
- `lanchat.ico` — آیکون پنجره و فایل اجرایی ویندوز.
- `requirements.txt` — کتابخانه‌های موردنیاز پایتون.
- `.github/workflows/build-windows.yml` — دستورهای GitHub Actions برای ساخت EXE مستقل.
- `README.md` — معرفی، محدودیت‌ها و راهنمای توسعه.

## نقشهٔ بخش‌های main.py

| تابع/کلاس | مسئولیت |
|---|---|
| ثابت‌های ابتدای فایل | نام و نسخه، پورت‌ها، شناسهٔ Beacon، مهلت آنلاین بودن و مسیر داده‌ها |
| `load_profile` / `save_profile` | خواندن و نوشتن تنظیمات و شناسهٔ پایدار دستگاه در `profile.json` |
| `save_message` | افزودن تاریخچه به فایل محلی `messages.txt`، در صورت فعال بودن ذخیره |
| `pack` / `recv_exact` / `recv_obj` | قالب بسته‌بندی TCP: چهار بایت طول بسته و سپس JSON با UTF-8 |
| `broadcast_targets` | پیدا کردن آدرس‌های Broadcast کارت‌های شبکهٔ IPv4 |
| `Events` | سیگنال‌های Qt برای انتقال رویداد از رشته‌های شبکه به رابط کاربری |
| `PeerNetwork` | کشف همتاها با UDP، دریافت پیام با TCP، ارسال پیام و به‌روزرسانی همتا‌به‌همتا |
| `SettingsDialog` | ساخت فرم تنظیمات و تحویل مقادیر انتخاب‌شده به پنجرهٔ اصلی |
| `LanChat` | رابط اصلی، فهرست کاربران، گروه‌های محلی، ارسال گروهی، اعلان و سینی سیستم |
| `main` | ساخت QApplication، تنظیم آیکون و اجرای حلقهٔ رویداد Qt |

## روند کشف کاربران و ارسال پیام

1. هر برنامه هنگام اجرا یک سرور UDP روی پورت `39873` و یک سرور TCP روی پورت `39872` راه‌اندازی می‌کند.
2. حلقهٔ `_beacon_loop` تقریباً هر سه ثانیه پیام حضور UDP (با شناسه، نام و شماره نسخه) را به Broadcastهای شبکه می‌فرستد.
3. `_udp_server` پیام‌های حضور سایر رایانه‌ها را می‌گیرد و با `_update_peer` نشانی IP، نام، نسخه و زمان آخرین مشاهده را نگه می‌دارد.
4. اگر از یک همتا بیش از `ONLINE_TIMEOUT` ثانیه پیامی نرسد، `_expire_peers` او را از فهرست آنلاین حذف می‌کند.
5. پیام متنی در `send_message` به‌صورت اتصال TCP مستقیم به IP گیرنده ارسال می‌شود. گیرنده درخواست را در `_handle_connection` پردازش و از طریق سیگنال `message_received` به رابط Qt تحویل می‌دهد.

**نکته:** این معماری سرور مرکزی ندارد. خاموش بودن گیرنده یا بسته بودن LanChat یعنی پیام در همان لحظه قابل تحویل نیست. گروه‌ها نیز در این نسخه تنظیمات محلی هر رایانه هستند و فهرست اعضای گروه بین دستگاه‌ها همگام نمی‌شود.

## مسیر دریافت و نمایش اعلان

- نقطهٔ ورود پردازش پیام دریافتی، `LanChat.receive_message` است.
- پیام پس از ثبت در تاریخچهٔ گفت‌وگو و فایل محلی، بر اساس `category` بررسی می‌شود.
- مقدارهای `group` و `broadcast` اعلان را حتی وقتی پنجرهٔ اصلی فعال است فراخوانی می‌کنند.
- `show_notification` متن را در پنجرهٔ شناور `toast` قرار می‌دهد، پنجره را روی صفحه می‌آورد و تایمر `toast_timer` را با مدت تنظیم‌شده شروع می‌کند.
- در کنار پنجرهٔ شناور، اعلان System Tray و صدای ویندوز نیز به‌صورت best-effort فراخوانی می‌شوند؛ اما پنجرهٔ شناور مسیر اصلی نمایش قابل‌مشاهده است.

اگر اعلان را تغییر می‌دهید، حتماً سناریوی «پنجرهٔ اصلی باز و فعال»، «برنامه مخفی در System Tray» و «چند پیام پیاپی» را جداگانه آزمایش کنید. ویجت‌های Qt را مستقیماً از رشتهٔ شبکه تغییر ندهید؛ از سیگنال‌های تعریف‌شده در `Events` استفاده کنید.

## تنظیمات و اطلاعات محلی

تمام اطلاعات کاربر در مسیر `%APPDATA%\LanChat` نگهداری می‌شود:

- `profile.json` — شناسهٔ ثابت نصب، نام، پوسته، فونت، رنگ‌ها و گزینه‌های برنامه.
- `messages.txt` — متن پیام‌های ثبت‌شده، فقط در صورت روشن بودن گزینهٔ ذخیره پیام.
- `updates` — فایل EXE دریافت‌شده از همتای دارای نسخهٔ جدیدتر.

برای آزمایش تمیز می‌توان از برنامه خارج شد و از `profile.json` نسخهٔ پشتیبان گرفت؛ حذف آن شناسهٔ جدیدی برای آن نصب می‌سازد. فایل تاریخچه را بدون اطلاع کاربر حذف یا ارسال نکنید.

## توسعه و ساخت نسخه

1. Python 3.11 را نصب کنید.
2. در پوشهٔ پروژه اجرا کنید: `python -m venv .venv`
3. محیط مجازی را فعال و وابستگی‌ها را نصب کنید: `pip install -r requirements.txt`
4. اجرای توسعه‌ای: `python main.py`
5. بررسی نحوی: `python -m py_compile main.py`
6. برای ساخت EXE محلی از دستور PyInstaller موجود در workflow استفاده کنید یا GitHub Actions را اجرا کنید.

در هر انتشار، مقدار `APP_VERSION` در `main.py` و نام Artifact در `.github/workflows/build-windows.yml` را با هم به‌روز کنید. نسخهٔ برنامه در Beacon فرستاده می‌شود؛ تغییر نسخه باعث می‌شود دیگران نسخهٔ جدیدتر را در فهرست کاربران تشخیص دهند.

## نکات امنیتی و سازگاری

- ارتباط TCP/UDP در این پروژه رمزنگاری یا احراز هویت رمزنگاری‌شده ندارد؛ آن را فقط در شبکهٔ مورداعتماد استفاده کنید.
- به‌روزرسانی همتا‌به‌همتا با SHA-256 خرابی فایل در مسیر انتقال را بررسی می‌کند، اما این امضا یا اثبات اصالت ناشر نیست. دریافت خودکار فایل به معنی اعتماد قطعی به فرستنده نیست.
- درخواست توقف ارسال، کنترل نرم‌افزاری بین نسخه‌های سازگار است و محدودیت امنیتی غیرقابل دور زدن نیست.
- گروه‌ها محلی‌اند؛ برای گروه مشترک واقعی باید پروتکل همگام‌سازی اعضا طراحی و با نسخه‌های قدیمی سازگار شود.
- هر تغییر شبکه‌ای را حداقل روی دو رایانهٔ واقعی، با فایروال روشن و در شبکهٔ واقعی مقصد آزمایش کنید. تست نحوی به‌تنهایی عملکرد شبکه و اعلان ویندوز را تضمین نمی‌کند.
- ساخت فعلی GitHub Actions بر مبنای Python ویندوز ۶۴ بیتی است؛ برای Windows x86 باید Runner/محیط ساخت ۳۲ بیتی و وابستگی‌های ۳۲ بیتی جداگانه فراهم شود.
